# 지표 방법론

## 1. 용어

| 용어 | 뜻 | 예 |
|---|---|---|
| **KGI** | Key Goal Indicator. 최종 목표지표. 사업의 성패를 한 숫자로 말한 것 | 연매출 250,000천원 |
| **CSF** | Critical Success Factor. KGI 달성에 반드시 성공해야 하는 요인 | 기관·학교 납품 확대 |
| **KPI** | Key Performance Indicator. CSF의 달성 정도를 재는 지표 | 신규 거래처 수, 견적 발송 건수 |

KGI는 "무엇을 이룰 것인가", CSF는 "그러려면 무엇이 되어야 하는가", KPI는 "그것이 되고 있는지 무엇으로 아는가"다.

## 2. 결과지표와 선행지표

| | 결과(R, lagging) | 선행(S, leading) |
|---|---|---|
| 성격 | 효과 | 원인 |
| 시점 | 나중에 확인 | 지금 실행 |
| 통제 | 직접 조작 불가 | 직접 조작 가능 |
| 주기 | 월·분기 | 주·월 |
| 용도 | 점검회의에서 가정 검증 | 실행회의에서 만회 |

구분 기준은 **통제 가능성**이다. "매출을 올려라"는 실행할 수 없는 지시이고 "이번 주 견적 10건"은 실행할 수 있는 지시다.

결과지표가 나빠졌을 때는 이미 손쓸 수 없다. 11월 매출 미달이 확정되는 순간 그것은 9~10월 활동량의 청구서일 뿐이다. 그래서 선행지표가 필요하다.

### 지표 계층

한 지표가 아래 단계에서는 결과이고 위 단계에서는 선행일 수 있다.

```
S1 견적 발송 ─┐
             ├→ R2 신규 거래처 수 ─→ R1 납품 매출 ─→ KGI 연매출
S2 전환율   ─┘
```

R2는 S1×S2의 결과이면서 R1의 선행이다. 이것을 인정하고 사슬로 그려야 연결 지도가 성립한다.

## 3. 정합성 검산

**선행 목표를 전부 달성했을 때 결과 목표가 나와야 한다.** 나오지 않으면 둘 중 하나가 틀린 것이다.

### 표준 검산식

```
B2B 영업     제안 건수 × 수주 전환율 × 건당 단가          = 매출
반복 거래     기존 거래처 수 × 재구매율 × 평균 구매액       = 매출
체험·교육     회차 × 회차당 인원 × 평균 단가               = 매출
구독         신규 가입 × (1 − 이탈률) × ARPU × 개월       = 매출
온라인       방문자(UV) × 구매 전환율                     = 주문 건수
             주문 건수 × 객단가                          = 매출
콘텐츠       조회수 × 유입률 × 구매 전환율                 = 주문 건수
행사·박람회   상담 건수 × 리드 전환율 × 수주 전환율 × 단가   = 매출
채용·인력     지원자 수 × 합격률 × 온보딩 완료율            = 가용 인력
```

### 검산이 맞지 않을 때

1. 선행 목표를 올린다 — 실행 가능한가? 인력·시간이 되는가?
2. 결과 목표를 낮춘다 — 다른 채널이 그 몫을 메울 수 있는가?
3. 가정(전환율·단가)을 고친다 — 근거가 있는가?

어느 쪽이든 **무엇을 왜 바꿨는지 기록한다.** 조정 이력이 없으면 다음 점검에서 같은 논쟁을 반복한다.

### 채널 합계 검사

```
Σ 채널별 목표 = 잔여 KGI
```

이것이 어긋나면 나머지 계산은 볼 필요가 없다. `validate.py`가 먼저 검사한다.

## 4. 지표 개수

CSF당 결과 1~2개 + 선행 2~3개가 적정하다. 전체 40~60개를 넘으면 점검회의에서 다루지 못한다.

대신 **핵심 KPI 10~15개**를 뽑아 대시보드로 따로 낸다. 전체 표는 근거이고, 대시보드가 운영 도구다.

## 5. 흔한 실패

| 증상 | 원인 | 처방 |
|---|---|---|
| 지표는 많은데 뭘 해야 할지 모르겠다 | 전부 결과지표다 | 각 결과에 선행을 붙인다 |
| 목표는 있는데 근거가 없다 | 검산을 안 했다 | Phase 5 |
| 매월 "노력하겠다"만 반복된다 | 선행지표 측정체계가 없다 | 무엇을 언제부터 기록할지 지정 |
| 결과가 안 나오는데 원인을 모른다 | 연결 경로가 없다 | Phase 7 연결 지도 |
| 제출 후 근거를 못 댄다 | 제안값과 원문값을 안 나눴다 | Phase 8 코드 색인 |
| 기간 종료 직전에 일이 몰린다 | 리드타임 역산을 안 했다 | Phase 9 마감 일정 |

## 6. 운영

- **주간 실행회의** — 선행지표만 본다. "했나 안 했나", 못 했으면 그 주에 만회.
- **월간 점검회의** — 결과지표를 본다. 선행을 다 했는데 결과가 안 나왔다면 전환율·단가 가정을 고친다.

선행을 달성했는데 결과가 미달이면 실행의 문제가 아니라 **설계의 문제**다. 연결 지도의 "점검할 가정" 열이 그때 쓰인다.
