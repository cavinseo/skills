# KGI → CSF → KPI 전개

목표를 관리 가능한 지표로 바꾸는 절차다. 산출물은 보고서 한 벌(화면용 HTML + 흑백 인쇄용 HTML/PDF)이다.

이 스킬의 가치는 지표를 많이 나열하는 데 있지 않다. **선행지표 목표를 다 달성했을 때 결과지표 목표가 산술적으로 나오는가**를 검산하는 데 있다. 그 검산을 통과하지 못하는 지표 체계는 숫자가 아무리 많아도 관리에 쓸 수 없다. 아래 워크플로는 그 검산을 강제한다.

## 산출 방식

`assets/template.html` + `assets/theme-*.css` 가 렌더링을 담당한다. 작성자는 **`data.json` 하나만 만들면 된다.**

```bash
python3 scripts/validate.py data.json                        # 반드시 먼저
python3 scripts/render.py  data.json -o report.html          # 화면용 컬러
python3 scripts/render.py  data.json -o report_bw.html --bw  # 흑백 인쇄용
python3 scripts/to_pdf.py  report_bw.html report.pdf
```

지표 코드(S1…/R1…)는 렌더러가 문서 순서대로 자동 부여한다. 손으로 매기지 말 것.
필드 형식은 `references/data-contract.md`에 있다.

> 스크립트를 실행할 수 없는 환경(웹 채팅 등)이라면 절차만 따르고 표를 마크다운으로 내도 된다. 검산 단계는 생략하지 말 것 — 그게 이 방법의 전부다.

## Phase 0 — 시작 전 반드시 확인할 세 가지

이 셋을 놓치면 이후 계산이 전부 틀어진다. 자료에 없으면 **묻는다.** 추측하지 않는다.

1. **사업(평가) 종료일.** 잔여기간 계산의 전제다. "연말까지"라고 가정하지 말 것. 지원사업은 10·11월 종료가 흔하고, 한 달 차이로 필요 월평균이 30% 이상 달라진다. 실제로 이 한 가지 확인이 "12월 박람회 참가비가 사업비에 잡혀 있는데 그 행사가 사업기간 종료 후" 같은 치명적 문제를 드러낸다.
2. **현재 누적 실적과 그 기준일.** 갭 계산의 출발점.
3. **사업비 총액과 항목별 배분.** 집행도 지표다(Phase 6).

부수적으로 확인하면 좋은 것: 기존 거래처·채널 목록과 채널별 실적(배분의 근거가 된다), 리드타임이 있는 항목(인증·시험·출원 등).

## Phase 1 — 자료 읽기

**계획서류**에서: 사업모델, 목표시장, 제품군과 단가, 기존 판로와 채널별 실적, 사업비 항목별 금액.
**점검·실적류**에서: 전년 실적, 당해 목표, 추진현황.

점검표가 있으면 그 **항목 구분(수익창출·상품개발·인증·고객만족·마케팅·네트워킹 등)이 그대로 CSF 묶음**이 된다. 임의로 재분류하지 말고 그 체계를 따른다. 제출처가 그 틀로 읽기 때문이다.

## Phase 2 — KGI 확정과 갭 분석

최상위 KGI는 대개 매출이다. 보조 KGI는 점검표 항목별 목표에서 뽑는다.

```
잔여 목표   = 연간 목표 − 누적 실적
필요 월평균 = 잔여 목표 ÷ 잔여 개월수        ← 종료일 기준으로 계산
배수        = 필요 월평균 ÷ 기존 월평균
```

**배수가 2를 넘으면 그 사실 자체가 가장 중요한 발견이다.** 보고서 첫 화면에 배치한다. 지표를 예쁘게 정리하는 것보다 "지금 속도의 2.9배가 필요하다"를 먼저 알리는 것이 점검자료의 역할이다.

## Phase 3 — 매출 KGI를 채널로 분해

단일 숫자는 진단이 불가능하다. 반드시 채널로 나눈다. 예: 기관납품 + 체험운영 + 온라인.

배분 기준은 **기존 실적 비중**이다. 다만 실적 대비 과도한 채널은 낮추고 그 몫을 현실적인 채널로 옮긴다. 판단 근거를 코멘트에 남긴다.

> 실제 사례: 온라인 누적 실적이 4년간 2억이었는데 3개월에 4천만원을 배정한 초안이 있었다. 월 필요 주문건수를 역산하니 381건, 계획한 150건의 2.5배였다. 온라인을 2천만원으로 낮추고 차액을 기관납품으로 옮겨 정합을 맞췄다.

## Phase 4 — CSF별로 결과/선행 쌍 배치

- **결과(R)** — 성과를 확인하는 후행지표. 직접 조작 불가. 주기는 월·분기.
- **선행(S)** — 결과를 만드는 활동·과정지표. 이번 주에 실행 가능. 주기는 주·월.

구분 기준은 **통제 가능성**이다. "매출 43,333천원을 올려라"는 지시는 실행할 수 없지만 "이번 주 견적 10건"은 실행할 수 있다.

한 지표가 아래 단계에서는 결과이고 위 단계에서는 선행일 수 있다(신규 거래처 수 = 견적×전환율의 결과이면서 매출의 선행). 계층을 인정하고 Phase 7에서 사슬로 그린다.

**모든 CSF에 선행지표를 최소 하나 둔다.** 선행이 없는 CSF는 관리 수단이 없는 CSF다.

## Phase 5 — 정합성 검산 (이 스킬의 핵심)

선행 목표를 모두 달성했다고 가정하고 결과 목표가 나오는지 **계산한다.**

```
견적 10건/월 × 전환율 30%      = 3건/월
3건 × 거래처당 5,000천원        = 15,000천원/월
× 3개월                        = 45,000천원   ← 결과 목표와 일치하는가?
```

자주 쓰는 검산식:

| 영역 | 검산식 |
|---|---|
| B2B 영업 | 제안 건수 × 수주 전환율 × 건당 단가 = 매출 |
| 반복 거래 | 기존 거래처 수 × 재구매율 × 평균 구매액 = 매출 |
| 체험·교육 | 회차 × 회차당 인원 × 평균 단가 = 매출 |
| 온라인 | 방문자 × 구매 전환율 = 주문 건수, × 객단가 = 매출 |
| 콘텐츠 | 조회수 × 유입률 × 구매 전환율 = 주문 |

맞지 않으면 선행 목표나 결과 목표 중 하나가 틀린 것이다. 그대로 두지 말고 조정한 뒤 **무엇을 왜 바꿨는지 코멘트에 남긴다.** 채널 합계는 잔여 KGI와 정확히 일치해야 한다(`validate.py`가 검사한다).

## Phase 6 — 기간·예산 관리를 별도 CSF로

지원사업·수탁사업에서는 매출만큼 중요하다. 사업비 항목별로 집행액·집행 시한·증빙 정리를 각각 지표로 둔다. 이렇게 하면 **기간 밖으로 새는 활동과 예산이 자동으로 드러난다.**

리드타임이 있는 항목은 종료일에서 역산해 **접수·발주 마감일**을 목표에 명시한다(예: 인증 시험 6주 → 종료 6주 전이 접수 마감).

## Phase 7 — 코드 부여와 연결 지도

선행은 S1…, 결과는 R1…을 문서 순서대로 부여하고, 전개표에서 **CSF 다음 독립 열**로 표기한다. 유형 배지 아래 작은 글씨로 넣으면 보이지 않아 쓸모가 없다.

연결 지도는 두 개의 표로 만든다.

- **산출 체인**: 채널별로 `선행지표 → 산출식 → 결과 → 검산(✓)`. 마지막 행에 합계와 KGI 일치 확인.
- **연결 경로**: `선행지표 → 경유 → 최종 기여 → 선행 달성·결과 미달 시 점검할 가정`.

마지막 열이 실전에서 가장 쓸모 있다. 구체적으로 쓴다. "조회수는 늘었는데 유입이 없다면 콘텐츠가 제품이 아니라 공정만 보여준 것" 같은 식으로, 원인 후보를 지목한다.

## Phase 8 — 근거 출처 표기

원자료에 수치가 없어 역산·통례로 제시한 값은 **전부 「제안」으로 표시**하고, 부록에 코드 색인을 만들어 지표별 근거를 `계획서 / 점검표 / 역산 제안`으로 구분한다. 제안값 개수를 집계해 본문에 밝힌다.

경험상 전체 지표의 절반 이상이 제안값이 된다. 그 비율을 숨기면 근거 없는 수치를 확정 목표처럼 제출하는 셈이 된다. 부록에 한 문장으로 명시한다.

> 확정 전까지 제안값은 목표가 아니라 **가설**이다.

## Phase 9 — 마감 일정 역산

기간별로 `목표(누적) / 반드시 끝나야 할 일 / 마감 리스크` 표를 만든다. 사업기간 밖 활동은 별도 행으로 빼고 "사업비 집행 불가"를 명시한다.

## Phase 10 — 점검 의견

보고서의 실질적 가치는 여기 있다. 우선 확인할 것:

- 필요 배수가 현실적인가
- 사업기간 밖으로 새는 활동·예산이 있는가
- 선행지표 측정체계가 실제로 존재하는가 (대개 없다 — 언제부터 무엇을 기록할지 지정한다)
- 목표 달성의 가장 빠른 레버는 무엇인가 (신규 발굴보다 기존 거래처 재구매가 빠른 경우가 많다)
- "완료 여부"형 이정표에 후속 결과지표가 붙어 있는가
- 리드타임 항목의 접수 마감이 지났거나 임박하지 않았는가

각 코멘트는 제목 한 줄 + 설명 한 문단으로 쓴다.

## 산출물 구성

```
01 KGI 체계          타일 + 갭 분석 막대
02 KGI → CSF → KPI   항목별 전개표 (CSF·코드·KPI·유형·단위·기준·목표·현황·주기)
03 선행 → 결과 연결   산출 체인 + 연결 경로
04 마감 일정          기간별 역산표
05 핵심 KPI 대시보드  10~15개, 상태 칩
06 점검 의견          코멘트 5~7건
부록 KPI 코드 색인    전체 지표의 이름·목표·근거
```

## 인쇄·배포

제출용은 **흰 바탕 흑백**이 기본이다. `--bw` 스타일은 색 대신 굵기·테두리·빗금·도형으로 구분한다(결과=채움 배지, 선행=테두리 배지, 제안=점선, 상태=●/◆/○). 흑백 레이저로 뽑아도 구분이 살아 있다.

세부 규칙과 문제 해결은 `references/print-and-export.md` 참조.

## 검증

내보내기 전 확인한다.

- [ ] `validate.py` 가 error 0
- [ ] 채널 목표 합계 = 잔여 KGI
- [ ] 모든 결과지표에 대응 선행지표가 있고 산술적으로 맞물린다
- [ ] 모든 역산 제안값에 「제안」 표기
- [ ] 잔여 개월수가 **사업종료일** 기준으로 계산됐다
- [ ] 사업비 집행 시한이 사업기간 안에 있다
- [ ] PDF를 실제로 열어 표 잘림·빈 페이지를 확인했다
