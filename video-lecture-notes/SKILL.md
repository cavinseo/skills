# Video Lecture Notes

강의 영상을 "본 사람처럼" 정리하는 것이 목표다. 자막 요약기와 다른 점은 두 가지다: (1) 화면에 있던
슬라이드·판서·도표를 함께 보고, (2) 언제 무엇을 말했는지 타임스탬프로 되짚을 수 있게 남긴다.
그래서 파이프라인은 항상 **화면과 음성을 시간축에서 합친 분석 패킷(`timeline.md`)** 을 먼저 만들고,
노트는 그 패킷을 읽고 쓴다. 패킷 없이 자막만 보고 쓴 노트는 이 스킬의 결과물이 아니다.

## 0. 시작 전 30초 체크

1. `python <skill>/scripts/doctor.py` — 도구·네트워크 상태를 한 번에 본다. 처음 쓰는 환경이면 반드시.
2. 어느 환경인지 확인한다. **Cowork/클라우드 샌드박스는 youtube.com과 huggingface.co가 막혀 있다.**
   그 경우의 우회(연결된 컴퓨터에서 받기, 파일 첨부, 자막 붙여넣기, sherpa-onnx 엔진 자동 전환)는
   `references/setup-and-environments.md` 에 정리돼 있다. 막힌 걸 확인한 뒤에 사용자에게 알려라 —
   추측으로 "안 됩니다"라고 하지 말 것.
3. 사용자에게 물을 것은 딱 두 가지, 그것도 답을 이미 알면 묻지 않는다:
   - 언어(`--lang ko|en`): 모르면 자동 감지지만, 알면 지정하는 편이 훨씬 정확하다.
   - 산출물: 기본은 마크다운 노트. HWPX/DOCX/PPT/프로젝트 축적은 노트가 나온 뒤에 파생한다.

## 1. 파이프라인 실행

```bash
python <skill>/scripts/run_all.py "<youtube-url 또는 파일경로>" --out work/<slug> --lang ko --model small
```

내부 순서와 산출물 (각 단계는 따로 실행할 수도 있다):

| 단계 | 스크립트 | 만들어지는 것 |
|------|----------|---------------|
| 1 다운로드/복사 | `fetch.py` | `source.mp4`, `meta.json`(제목·채널·챕터·설명), `subs.<lang>.vtt`(있으면) |
| 2 전사 | `transcribe.py` | `transcript.json/.srt/.txt` — faster-whisper, HF 차단 시 sherpa-onnx 자동 |
| 3 화면 캡처+OCR | `keyframes.py` | `frames/fNNNN_mm-ss.jpg`, `frames.json`(OCR 포함), `sheets/sheet_NN.jpg` |
| 4 정렬 | `merge.py` | **`timeline.md`** / `timeline.json` — 화면별 [OCR + 그때 말한 내용], `chunks/chunk_NN.md` (10분 단위, 분량 예산 포함) |
| 5 검사 | `coverage.py` | 노트 완성 후: 구간별 인용 분포, 중간 구간 누락 FAIL, `ledger.md`(빠진 항목 후보) |

실행 요령:
- 긴 영상(30분 이상)은 백그라운드로 돌리고 진행 상황을 사용자에게 알린다. CPU에서 `small`은 대략
  실시간의 0.3~1배, `medium`은 2~3배 걸린다.
- 이미 공식 자막(자동 생성 아님)이 있는 영상이고 사용자가 빠른 결과를 원하면 `--prefer-subs`.
  자동 생성 자막은 한국어 품질이 들쭉날쭉하므로 기본은 Whisper다.
- 다시 돌릴 때는 `--skip-existing` 으로 이미 있는 단계를 건너뛴다(키프레임 파라미터만 바꿔 재실행 등).
- 화면 종류에 따라 키프레임 민감도를 조정한다: 슬라이드 강의는 기본값, 판서/화이트보드는
  `--hash-dist 10 --min-gap 20`, 편집이 많은 영상은 `--max-frames 60`. 결과가 200장을 넘거나
  5장도 안 되면 파라미터가 안 맞는 것이다.
- 오디오만 있는 파일(팟캐스트, 녹음)은 자동으로 화면 단계를 건너뛰고 3분 단위로 묶는다.

## 2. 분석 패킷 읽기 — 노트 쓰기 전에 실제로 "본다"

가장 흔한 실패는 **영상의 앞과 뒤만 반영된 노트**다. 원인은 셋이 겹친다: 긴 입력의 중간이 흐려지는
모델의 성향(lost in the middle), 서론·결론에 요약 문장이 몰려 있는 강의의 구조, 그리고 전체를
한 번에 읽고 한 번에 쓰는 작업 방식. 그래서 이 스킬은 "한 번에 읽고 한 번에 쓰기"를 금지한다.

**15분 이하 영상**: `timeline.md` 를 처음부터 끝까지 읽고 바로 3단계로 간다.

**15분 초과 영상 — 청크별 map, 그 다음 reduce**:
1. `merge.py` 가 이미 `chunks/chunk_NN.md` (기본 10분 단위)를 만들어 두었다. 각 청크 머리에
   발화량과 **분량 예산**(그 청크에서 강사가 말한 양에 비례)이 적혀 있다.
2. 청크를 **1번부터 순서대로, 하나씩** Read 하고, 읽은 직후 `chunks/chunk_NN.notes.md` 를 쓴다.
   내용: 이 청크의 소제목 후보(타임스탬프 포함), 예산만큼의 핵심 문장, 정의된 용어, 숫자·고유명사,
   인용할 문장, 화면에서 본 것. 다음 청크를 열기 전에 반드시 이 파일을 쓴다 — 미루면 중간 청크가
   기억에서 밀려난다. 청크 하나가 아무리 시시해 보여도 예산의 절반 이하로 쓰지 않는다(강사가
   그만큼 말했다는 뜻이다).
3. 모든 `chunk_NN.notes.md` 가 있으면 그것들만 다시 읽고(원본 timeline은 필요한 확인에만) 최종
   노트를 쓴다. 구간별 상세 정리의 분량은 청크 예산 비율을 따른다 — 서론·결론이 중간보다 길면
   그 자체가 편향의 증거다.
4. 병렬이 가능한 환경(서브에이전트)이면 청크별 요약을 각각 다른 에이전트에 맡겨도 좋다. 모든 청크가
   "첫 번째 입력"이 되므로 위치 편향이 구조적으로 사라진다. 단 최종 reduce는 한 곳에서 한다.

공통:
- `sheets/sheet_NN.jpg` 를 Read 도구로 본다. 한 장에 12개 화면이 들어 있어 전체 흐름이 한눈에 잡히고,
  OCR이 놓친 도표·수식·손글씨를 직접 확인할 수 있다. OCR 텍스트는 힌트일 뿐, 도표가 중요한 화면은
  `frames/` 원본을 열어 본다. 시트도 **전부** 본다 — 중간 시트를 건너뛰는 것이 같은 편향이다.
- 읽으면서 표시해 둘 것: 구간 경계(주제가 바뀌는 시각), 강사가 정의한 용어, 숫자와 고유명사,
  반복해서 강조한 문장, 근거가 약한 주장. 이것들이 노트의 뼈대다.
- 유튜브 챕터(meta.json)나 "오늘 세 가지를 말씀드리겠습니다" 같은 강사의 예고를 목차의 **가설**로만
  쓴다. 실제 구간 경계는 timeline에서 확인한 것으로 잡는다 — 강사는 예고한 순서대로 말하지 않는다.

## 3. 노트 작성

`assets/note_template.md` 의 구조를 따른다. 섹션 이름은 유지하되 영상에 맞지 않는 섹션은 뺀다
(예: 프레임워크가 없는 대담이면 그 섹션 삭제). 작성 원칙:

- **강사의 말을 보존한다.** 요약은 압축이지 재해석이 아니다. 강사가 든 예시, 숫자, 비유는 그대로
  살리고, 내 해석은 "비판적 검토"와 "적용 아이디어"에만 쓴다.
- **모든 구간 제목과 인용에 타임스탬프**를 단다. 사용자가 그 지점으로 되돌아가 확인할 수 있어야
  노트가 신뢰를 얻는다. 유튜브면 `https://youtu.be/<id>?t=<초>` 링크로 만들어 준다.
- **화면을 인용한다.** 노트가 언급하는 슬라이드·도표는 `![제목](frames/f0007_00-12-40.jpg)` 로 3~8장
  임베드한다. 강사 얼굴만 나온 프레임은 넣지 않는다.
- **전사 오류를 조용히 바로잡는다.** Whisper는 고유명사·전문용어를 자주 틀린다(예: "린 스타트업"→
  "린 스타트 업", 영어 이름 음차). OCR 텍스트·영상 설명·문맥으로 확인되는 것만 고치고, 확신이 없으면
  `(전사 불확실)` 표시를 남긴다. 신뢰도 메모에 전사 엔진·모델과 이런 한계를 한 줄 적는다.
- **사용자 맥락에 맞춘 적용 섹션.** 사용자가 교육자·컨설턴트·창업자 등 어떤 맥락에서 이 영상을
  보는지 알면 "적용 아이디어"는 그 맥락으로 쓴다. 모르면 일반적으로 쓰되 짧게.
- 길이 기준: 10분 영상 ≈ 노트 1~1.5쪽, 60분 강의 ≈ 4~6쪽. 목차 표는 구간 8~20개가 적당하다.

`WORKDIR/notes.md` 로 저장한다.

### 3-1. 전달 전 커버리지 검사 (필수)

```bash
python <skill>/scripts/coverage.py WORKDIR --ledger
```

노트에 인용된 타임스탬프를 시간축에 뿌려 발화량과 비교한다. 10분 구간 중 발화가 있는데 인용이 하나도
없는 구간이 있거나, 중간 1/3의 인용 밀도가 전체 평균의 35% 미만이면 FAIL 이다. FAIL 이면 해당 구간의
`chunks/chunk_NN.md` 로 돌아가 다시 읽고 내용을 보강한다 — 타임스탬프만 흩뿌려 통과시키는 것은
검사의 목적을 정확히 배반하는 일이다. `ledger.md` 에는 영상에 나왔지만 노트에 없는 고유명사·숫자·
슬라이드 제목 후보가 뜬다(잡음이 섞여 있으니 판단은 직접). 여기서 중요한 것을 놓쳤으면 추가한다.
통과한 결과(구간별 인용 분포 표)를 노트 머리의 신뢰도 메모에 한 줄로 남긴다.

SendUserFile로 전달한다. 프레임을 임베드했으면 `notes.md`와 `frames/`를 함께 zip으로 준다(링크가
살아 있도록).

## 4. 파생 산출물

노트가 나온 뒤 사용자가 원하는 형태로 변환한다. 매핑 규칙은 `references/output-formats.md` 에 있다:
HWPX/DOCX 보고서(hwpx/docx 스킬), PPT 재구성(pptx 스킬 — "다시 가르칠 덱"인지 "원본 슬라이드
아카이브"인지 구분), 프로젝트 지식베이스 축적(`videos/INDEX.md` 관리), 구조화 JSON.

프로젝트가 붙어 있는 세션에서는 묻지 않아도 노트를 프로젝트에 저장한다 — 이 스킬을 쓰는 사용자는
영상을 여러 편 쌓아 검색하려는 경우가 대부분이다. 단, 프레임 이미지는 프로젝트에 넣지 않는다.

## 5. 여러 편 한꺼번에

재생목록이나 URL 여러 개를 받으면 `fetch.py` 는 `--no-playlist` 라서 한 편씩이다. 각 영상을
`work/<slug>` 로 따로 돌리고(순차 실행 — CPU 전사를 병렬로 돌리면 느려진다), 편별 노트를 만든 뒤
마지막에 `series-overview.md` 로 공통 주제·차이·순서 추천을 정리한다.

## 흔한 실패와 대처

| 증상 | 원인 | 대처 |
|------|------|------|
| `Tunnel connection failed: 403` (yt-dlp) | 샌드박스에서 유튜브 차단 | 연결된 컴퓨터에서 받기 / 파일 첨부 요청 (`references/setup-and-environments.md`) |
| faster-whisper 모델 다운로드 실패 | huggingface.co 차단 | `--engine sherpa` (자동 전환됨). 첫 실행 시 GitHub에서 모델 640MB 다운로드 |
| 전사가 일본어/중국어로 나옴 | 언어 자동 감지 오류 | `--lang ko` 지정 후 `transcript.json` 삭제하고 재실행 |
| 키프레임 0~2장 | 화면 변화가 작음(판서, 줌 녹화) | `--hash-dist 4 --sample 1` |
| 키프레임 수백 장 | 카메라 영상·애니메이션 | `--hash-dist 12 --min-gap 15 --max-frames 80` |
| OCR이 한글을 못 읽음 | `tesseract-ocr-kor` 미설치 | 설치하거나 `--no-ocr` 후 contact sheet를 직접 보고 쓴다 |
| 노트가 자막 요약처럼 밋밋함 | sheets를 안 봤음 | 2단계로 돌아가 화면을 실제로 본다 |
| 앞·뒤만 자세하고 중간이 텅 빔 | 전체를 한 번에 읽고 씀 | `coverage.py` FAIL 구간의 chunk를 다시 읽고 `chunk_NN.notes.md`부터 다시 쓴다 |

## 파일 안내

- `scripts/run_all.py` — 전체 실행. `fetch.py`, `transcribe.py`, `keyframes.py`, `merge.py` 는 단계별.
- `scripts/coverage.py` — 노트 커버리지 검사 + 누락 원장. `scripts/doctor.py` — 환경 점검. `scripts/make_test_video.py` — 네트워크 없이 테스트용 강의 영상 생성.
- `assets/note_template.md` — 노트 골격.
- `references/setup-and-environments.md` — 설치, 모델 선택, 클라우드/로컬/연결된 컴퓨터별 동작.
- `references/output-formats.md` — HWPX/DOCX/PPT/프로젝트/JSON 변환 규칙.
